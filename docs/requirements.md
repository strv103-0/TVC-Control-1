# 요구사항 및 설계 목표

> **2026-09-09 기준 시작점 값입니다.** 확정값이 아닙니다.
> 시뮬레이션과 CAD를 오가며 반복 갱신합니다. 절차는 [7절](#7-값-갱신-원칙) 참고.

## 1. 프로젝트 목표

프로펠러 추력의 방향을 짐벌로 꺾어(TVC) 로켓형 동체의 자세를 능동 제어한다.

1. **호버링** — 기체를 세운 자세로 공중에 유지
2. **위치 제어** — 원하는 지점으로 이동하고 그 자리를 유지

## 2. 기체 사양

| 항목 | 시작점 값 | 근거 | 확정 |
|---|---|---|---|
| 전장 `L_body` | 600 mm | 관성모멘트 확보와 취급성의 절충 | ☐ |
| 직경 | 90 mm | 배터리·전자부 수납 가능한 최소 수준 | ☐ |
| 이륙 중량 `m` | 800 g | 9~10인치 프로펠러로 T/W 1.8 확보 가능 | ☐ |
| 추력 `T` | 14 N | T/W = 1.8 (호버 필요추력 7.85 N) | ☐ |
| 추력 대 중량비 | 1.8 | 1.5 이상 필요, 여유 포함 | ☐ |
| **모멘트 팔 `L`** | 250 mm | 짐벌 회전중심 ~ 무게중심 거리 | ☐ |
| 짐벌 가동 범위 | ±12° (2축) | 제어 권한과 기구 간섭의 절충 | ☐ |
| 목표 비행 시간 | 60 초 | 초기 시험 기준. 이후 상향 | ☐ |

> `L`(모멘트 팔)이 제어 성능을 좌우하는 가장 중요한 값입니다.
> 제어 모멘트가 `M = T · L · sin δ` 로 결정되기 때문입니다.
> 자세한 유도는 [dynamics-and-control.md](dynamics-and-control.md) 참고.

## 3. 시뮬레이션 파라미터

2절 값에서 유도한, 모델에 직접 들어가는 값입니다.

| 기호 | 값 | 산출 근거 |
|---|---|---|
| `m` | 0.8 kg | 2절 |
| `I` | 0.024 kg·m² | 세장형 막대 근사 `I = (1/12)·m·L_body²` — **CAD 완성 후 실측값으로 교체** |
| `L` | 0.25 m | 2절 |
| `T` | 14 N | 2절 |
| `g` | 9.81 m/s² | |
| `δ_max` | 12° | 2절 |
| `δ̇_max` | 600 deg/s | 서보 사양 `0.10 s/60°` 환산 — **서보 확정 후 갱신** |
| `τ_servo` | 20 ms | 지령~반응 지연 추정 — **실측 후 갱신** |
| `f_ctrl` | 250 Hz | 4절 |

### 검산

`sim/matlab/params.m` 실행 결과.

```
플랜트 이득     K_att = T_hover·L / I = 7.85 × 0.25 / 0.024 ≈ 81.8  [rad/s² per rad]

호버 기준 (제어기 설계점)
  M = 7.85 × 0.25 × sin(12°) ≈ 0.41 N·m  →  θ̈ ≈ 17.0 rad/s²  (974 deg/s²)
최대 추력 기준
  M = 14.1 × 0.25 × sin(12°) ≈ 0.73 N·m  →  θ̈ ≈ 30.6 rad/s²  (1753 deg/s²)
```

제어 권한은 충분하다.

> **제어기 설계에는 `T_hover`를 쓴다.** 모멘트는 그 순간의 추력에 비례하는데,
> 제어기는 호버 부근에서 동작하기 때문이다.
> `T_max`로 설계하면 플랜트 이득을 1.8배 과대평가해 실기에서 진동한다.

## 4. 제어 요구사항

| 항목 | 목표값 |
|---|---|
| 제어 루프 주기 | 250 Hz |
| 자세 추정 | IMU (자이로+가속도) 상보/칼만 필터 |
| 제어기 구조 | 위치 → 자세각 → 각속도 캐스케이드 |
| 정지 호버 자세 오차 | ±2° 이내 |

### 루프별 목표 대역폭

| 루프 | 교차주파수 | 제어기 | 비고 |
|---|---|---|---|
| 각속도 (안쪽) | 3.5 Hz | P 또는 PI | **서보 지연이 상한을 결정** |
| 자세각 | 0.9 Hz | P | |
| 위치 (바깥) | 0.22 Hz | PD | 비최소위상 때문에 느려야 함 |

각 루프 사이를 4배 벌려 시간 척도를 분리한다.

> **2026-09-09 발견**: 처음에 각속도 루프를 4~8 Hz로 적었으나,
> 가정한 서보 지연 20 ms와 양립하지 않는다.
> 위상지연 30° 기준 상한이 `ω_c ≤ 0.52/τ = 26 rad/s ≈ 4.1 Hz` 이므로,
> 여유를 두어 3.5 Hz로 낮추고 나머지 루프를 4배 간격으로 재배치했다.

### 서보 요구사양 (역산)

원하는 대역폭에서 거꾸로 뽑은 서보 선정 기준이다.

| 목표 각속도 루프 | 허용 서보 지연 |
|---|---|
| 3.5 Hz | ≤ 24 ms |
| 6 Hz | ≤ 14 ms |
| 8 Hz | ≤ 10 ms |

**더 빠른 자세 응답이 필요하면 게인이 아니라 서보를 바꿔야 한다.**
지연이 큰 서보에 게인만 올리면 진동하다 발산한다.

## 7. 값 갱신 원칙

이 문서의 값은 **한 번 정하고 끝나는 것이 아니라, 시뮬레이션과 CAD를 오가며 수렴시킨다.**

```
        ┌─────────────────────────────────────────┐
        │                                         │
        ▼                                         │
   설계값 (이 문서)  ──→  params.m  ──→  Simulink 시뮬레이션
        ▲                                         │
        │                                         ▼
        │                                   성능 확인 · 게인 탐색
        │                                         │
        └──────────  CAD 설계 · 실측  ←───────────┘
```

### 두 방향의 갱신

**① 시뮬레이션 → 설계값**
게인을 튜닝하다 보면 "이 값으로는 목표 성능이 안 나온다"는 결론이 나온다.
모멘트 팔을 늘려야 하거나, 더 빠른 서보가 필요하거나, 기체가 너무 무겁다는 식이다.
이때 설계값을 바꾸고 다시 시뮬레이션한다.

**② CAD → 설계값**
기구 설계를 하다 보면 근사값이 실제와 다르다는 것이 드러난다.
특히 **관성모멘트**는 세장형 막대 근사로 시작했으므로, CAD 완성 후
Fusion이 계산한 실제 관성텐서로 반드시 교체해야 한다.
무게중심 위치가 바뀌면 모멘트 팔 `L`도 함께 바뀐다.

`I`와 `L`이 바뀌면 플랜트 이득 `K_att = T·L/I`가 바뀌므로 **게인을 다시 잡아야 한다.**

### 어디에 무엇을 적는가

값이 두 곳에 흩어지면 반드시 어긋난다. 역할을 나눈다.

| 파일 | 역할 | 언제 고치나 |
|---|---|---|
| `sim/matlab/params.m` | 시뮬레이션이 실제로 읽는 값 | 시뮬레이션을 돌릴 때마다 자유롭게 |
| `docs/requirements.md` (이 문서) | **확정된** 설계값과 그 근거 | 값이 확정됐을 때만 |

시뮬레이션 중 이것저것 바꿔보는 단계에서는 `params.m`만 고친다.
값이 확정되면 이 문서에 반영하고 **왜 그 값이 되었는지**를 함께 적는다.
그러면 이 문서가 탐색 과정의 소음 없이 결론만 담게 된다.

### 갱신 시 확인할 것

- [ ] `params.m`을 실행해 검산 출력과 경고를 확인했는가
- [ ] `I` 또는 `L`이 바뀌었다면 게인을 다시 잡았는가
- [ ] 서보 요구사양(4절)을 여전히 만족하는가
- [ ] 이 문서의 8절에 변경 이유를 남겼는가
