# 시뮬레이션

제어기 설계와 검증을 여기서 한다. 실기체에 올리기 전에 게인·짐벌 한계·서보 요구사양을 확정한다.

```
sim/
├─ simulink/   Simulink 모델 (.slx) — 기체 동역학, 제어기
└─ matlab/
   └─ params.m   모든 시뮬레이션 파라미터 (질량 · 관성 · 게인 · 서보 사양)
```

## 사용법

Simulink 모델을 열기 **전에** 파라미터를 먼저 워크스페이스에 올린다.

```matlab
cd sim/matlab
params
```

검산 결과와 경고가 출력된다. 목표 대역폭이 서보 한계를 넘으면 경고가 뜨므로,
값을 바꿀 때마다 이 출력을 확인한다.

값의 근거와 갱신 절차는 [../docs/requirements.md](../docs/requirements.md) 참고.

필요한 MATLAB 제품은 [../docs/matlab-products.md](../docs/matlab-products.md) 참고.

## `.slx` 는 바이너리다 — 편집 규칙

Simulink 모델은 git이 **자동 병합하지 못한다.** 두 PC에서 동시에 고치면 한쪽을 버려야 한다.

1. 모델을 열기 전에 반드시 `.\tools\sync.ps1 start`
2. 작업을 마치면 반드시 `.\tools\sync.ps1 end "..."` — 다른 PC로 넘어가기 전에 push
3. 한 번에 **한 PC에서만** 편집

## 파라미터는 `.slx` 안에 하드코딩하지 않는다

질량·관성·게인 같은 값을 블록 다이얼로그에 직접 적으면
git diff로 "무엇이 언제 바뀌었는지" 추적할 수 없다.

`matlab/params.m` 같은 스크립트에 변수로 두고 블록에서는 변수명을 참조한다.
`.m`은 텍스트라 변경 이력이 그대로 남는다.

## 서보를 이상적으로 모델링하지 말 것

TVC 호버 기체가 실패하는 가장 흔한 원인은 제어 게인이 아니라 **구동기 한계**다.
아래를 모델에 넣지 않으면 시뮬에서 완벽한 게인이 실기에서 발산한다.

- 서보 각속도 제한 (사양의 `0.1s/60°` → `600 deg/s`로 환산)
- 지령 ~ 반응 지연 (수십 ms)
- 짐벌 각도 포화 (`GIMBAL_LIMIT_DEG`)
- 제어 루프 이산화 주기 (`CONTROL_HZ`)
